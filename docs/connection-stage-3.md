# 連線模式第三階段：主電腦媒體控制與主電腦捷徑

狀態：已實作，所有自動測試通過，兩邊已換上 C3 並重新連線。主電腦實際播放器與實際執行捷徑待使用者在實機驗證，等待確認。

## 交付內容

- **主電腦媒體控制**
  - 每個媒體組件右上角新增「來源：本機／主電腦」切換，與組件設定一起儲存（HomeWidgetSettings.MediaSource，預設本機）。
  - 選「主電腦」後，組件顯示主電腦正在播放的標題、演出者、播放狀態、進度與封面。上一首、播放／暫停、下一首都會控制主電腦的播放器。
  - 連接助手沿用 WPF 版的 Windows 媒體工作階段來源（MediaWidgetSource）：
    - 只在至少一個設為「主電腦」的組件顯示時訂閱，最後一個離開即取消。
    - 有變化時回報；播放中另外每 5 秒回報一次，讓進度保持更新。
  - 只有上一首、播放／暫停、下一首三種指令會送出。
  - 封面依需要取得，每首只取一次，上限 700 KB。Linux 版把封面存成使用者私有的暫存檔，因為組件只讀本機檔案。
  - 主電腦未連線時，組件說明原因，可切回本機；重新連上後自動恢復。
- **主電腦捷徑**
  - 不另設分區（使用者 2026-10-18 要求）：主電腦的捷徑和本機捷徑放在同一組分組中，依各自的分組顯示，分組選單一起套用。快捷導航頁已不再提供搜尋框（使用者 2026-10-18 要求），只以分組篩選。圖塊標示「主電腦」，尚未在主電腦確認的另標「需確認」。
  - 連線時按「＋ 新增」，編輯器最上方可選「儲存與執行位置」：本機（預設）或主電腦「名稱」，並說明兩者的差別。
    - 選主電腦時套用 Windows 規則，路徑填主電腦上的位置。
    - 已存在的捷徑只顯示所在位置，不能改。
    - 主電腦的捷徑可編輯、刪除、設定下次重新確認，並執行；複製、排序與拖動只適用本機捷徑。
  - 主電腦的捷徑存在主電腦（連接助手資料夾的 shortcuts.json）。
  - 主電腦是唯一的把關者：
    - 設備送來的每個捷徑都在主電腦重新驗證，不合規則就拒絕，並把原因顯示在設備上。
    - 確認紀錄只存在主電腦，從不傳給設備。設備送來的確認欄位一律忽略，所以設備無法把捷徑標成已確認。
    - 沿用 WPF 版的 ShortcutExecutor（已搬到 Secondary.Windows）與 ShortcutRunner，包括腳本 SHA256 檢查與執行期間的唯讀鎖定。
  - 第一次執行，或步驟、腳本內容變更後，確認視窗出現在主電腦的螢幕上：
    - 內容：哪臺設備要求、捷徑名稱、每個步驟的目標、參數與腳本 SHA256。
    - 預設焦點在「取消」，Enter 不會確認。關閉視窗、按 Esc 或 2 分鐘未回應都視為取消。
    - 設備端只顯示「等待主電腦確認」。
  - 執行時，設備顯示主電腦回報的步驟進度與結果。
  - 設備可按「取消執行」；設備進入遊戲模式、隱藏或斷線時，主電腦也會停止。已開啟的程式不會被關閉，與本機巨集相同。
  - 設備在遊戲模式時不執行：設備不會送出，連接助手在設備停在遊戲頁時也會拒絕。
  - 同一時間只執行一個。
  - Linux 版編輯主電腦捷徑時：
    - 選主電腦時停用檔案選擇器，因為這臺設備的檔案不在主電腦上，路徑請直接輸入主電腦的位置。
    - 含「視窗快捷鍵」步驟的捷徑無法在 Linux 編輯（Linux 編輯器沒有此步驟），但可以執行。
- **連接助手系統匣**：新增「媒體：設備正在顯示主電腦的播放內容／未使用」，以及「主電腦捷徑：N 個／正在執行「名稱」」。
- **共用與協定**
  - MediaWidgetSource 與 ShortcutExecutor 從 WPF 專案搬到 Secondary.Windows（命名空間 Secondary.Desktop），只搬移、不重構。
  - Secondary.Windows 與連接助手改用 net10.0-windows10.0.22621.0，以使用 Windows 媒體 API。
  - 新增訊息：
    - 媒體：media-watch、media-state、media-control、media-artwork。
    - 捷徑：shortcuts、shortcut-save、shortcut-delete、shortcut-reset、shortcut-run、shortcut-status、shortcut-cancel。
  - 請求的 id 欄位保留給請求編號：帶有 id 欄位的訊息會被拒絕，避免內容被覆寫。開發時曾因此讓捷徑 id 被蓋掉。

## 驗證方法

- 核心測試：Windows 341 項、Linux 342 項，新增 27 項。
  - 訊息：
    - 媒體狀態往返；拒絕過長標題與負數進度。
    - 確認紀錄不隨捷徑傳送，也無法偽造。
    - Windows 規則：拒絕相對路徑、其他腳本類型與網路路徑；清單略過重複與無效項目。
  - 迴路連線：
    - 組件開始顯示前不回報；兩個組件共用一個訂閱，最後一個離開才取消。
    - 控制指令限三種；封面每個只取一次，拒絕超過上限的封面。
    - 斷線時清除，重新連線後自動重新訂閱。
    - 捷徑清單、新增、主電腦拒絕的原因；執行時的等待確認、步驟與結果；設備取消；斷線時結束並說明。
    - 請求帶 id 欄位時被拒絕。
- WPF UI 檢查 6,779 項，新增 23 項。使用真的連接助手元件（媒體服務、捷徑服務、確認視窗），搭配假的播放器與只記錄不執行的執行器：
  - 媒體組件：切換來源並儲存、顯示主電腦的歌曲與狀態、播放／暫停控制主電腦並跟著更新、切回本機。
  - 快捷導航：
    - 連線時「＋ 新增」提供本機與主電腦兩個位置（預設本機）；選主電腦後存到主電腦的檔案。
    - 主電腦捷徑出現在自己的分組裡（不是獨立分區），圖塊標示主電腦；主電腦拒絕不合規則的捷徑。
    - 首次執行時主電腦跳出確認視窗（含設備名稱與目標）；確認前什麼都不執行，確認後才執行並記住。
    - 已確認的直接執行；修改步驟後重新確認；在主電腦取消就不執行。
    - 遊戲模式中不執行；刪除。
- Linux 外殼檢查：Windows 323 項、Linux 357 項，新增 17 項：
  - 媒體組件的來源切換、顯示與控制，切回本機後停止回報。
  - 用真的編輯器新增：
    - 預設本機，切到主電腦後接受 Windows 路徑並存到主電腦。
    - 主電腦捷徑出現在自己的分組並標示主電腦；保持本機則存在這臺設備。
  - 主電腦拒絕、含視窗快捷鍵的捷徑不在 Linux 編輯、既有主電腦捷徑的位置固定、執行時顯示等待確認與結果、刪除。
- 本機 UI 檢查照例暫時放寬 150% DPI 下已知的 44 DIP 導航檢查，跑完已還原。
- 實機：
  - Windows 執行 C3 連接助手，Surface 換上 C3 AppImage，重新啟動後自動連回。
  - 連接助手已連線、閒置時：30 秒平均約佔單核 0.21%，私有記憶體 17.7 MB，工作集 72 MB。

## 尚未驗證

- 主電腦實際播放器（例如 Spotify、瀏覽器）在 Windows 與 Linux 設備上的顯示、控制與封面。
- 實際在主電腦執行捷徑，包括確認視窗出現在主電腦螢幕、腳本與視窗快捷鍵步驟。
- 主電腦正在全螢幕遊戲時，確認視窗是否會蓋到遊戲上。設備在遊戲模式時不會送出執行，所以一般不會發生。
- Windows 設備連到另一臺 Windows 主電腦。

## 注意事項

- 主電腦捷徑存在連接助手的資料夾（%LOCALAPPDATA%\Secondary\Connect\shortcuts.json），與主電腦上 WPF 版 Secondary 的捷徑互不相通。
- Windows 設備編輯主電腦捷徑時，編輯器的「瀏覽」選的是這臺設備的檔案，路徑必須在主電腦上也存在；主電腦會在執行時檢查目標是否存在。
