# Linux 第二階段：首頁組件、時鐘、媒體、天氣與背景

狀態：已確認（2026-10-18），使用者指示進入 L3。

## 交付內容

- 共用層：
  - 組件幾何（八方向縮放、吸附與對齊線、找空位）與天氣服務搬入 Secondary.Shared，由兩個版本共用。
  - WPF 版改用薄轉接層呼叫共用幾何，對外介面與既有測試都不變。
  - `HomeSettings.IsLocalPath` 在 Linux 另外接受絕對路徑（`/home/...`），仍拒絕網路位置；Windows 行為不變。
- 首頁改為固定大小的組件畫布，不再跟著頁面捲動，與 WPF 版相同：
  - 「＋ 組件」可加入 10 種組件，最多 12 個，同類可重複。新組件會先找空白位置；空間已滿時會提示並放在最上層。也可從選單選取被遮住的組件。
  - 組件框：拖動標題移位，四角與四邊都能縮放、對側保持固定。依使用者要求，八個縮放把手全部放在邊框外，不再擋住標題列的拖動區；把手只在顯示時接受點擊，畫布也不裁切邊緣組件的外側把手。靠近畫布或其他組件 8 DIP 內會吸附並顯示虛線，按住 Alt 暫停吸附。Esc 取消拖曳並還原，放開時才保存。
  - 聚焦後可用方向鍵移動、Ctrl＋方向鍵縮放、Shift 加速。右鍵選單可移除組件，移除前會在視窗內確認。
  - 觸控：
    - 點一下組件即選取並顯示編輯框（觸控沒有滑鼠懸停）；點畫布空白處、選取其他組件或離開首頁時取消。
    - 選取後縮放把手放大到手指大小（角落 36 DIP、邊緣 28 DIP）。
    - 手指按住 0.6 秒且移動不超過 10 DIP，會開啟移除選單，組件不會移動也不會保存。
- 時鐘：
  - 數字、翻頁、指針三種樣式，外框依格式與字型量測，時間或日期變化（包括跨午夜）不會改變大小。
  - 翻頁約 420 ms，只翻動變化的數字；遇到減少動畫或高對比時立即停在靜態畫面。
  - 數字使用隨程式附帶的 Inter 字型，日期與中文由系統字型（Noto CJK）顯示。
- 其他組件：日曆、便箋（Ctrl+S 保存）、倒數計時、碼錶、待辦、計數器、時間進度、倒數日。行為、文字與字數上限都與 Windows 版相同，內容會隨組件大小調整。
- 媒體：
  - 透過 MPRIS（D-Bus）讀取播放中或暫停中的播放器，顯示標題、演出者、進度，以及上一首、播放／暫停、下一首。播放器不支援的操作會停用。
  - 只在組件顯示時監看播放器變化。
  - 封面只讀本機檔案（file://），不另外連網抓取播放器提供的網路封面。
- 天氣：與 Windows 共用 Open-Meteo 流程，包括城市候選、確認後保存座標、共用快取、過期與失敗狀態，以及資料來源與授權連結。
- 自訂首頁彈窗：時鐘樣式、24 小時制、秒數、日期、大小與位置、顏色與背景。檔案選擇經由桌面入口服務。按套用才保存，關閉或 Esc 會放棄變更。
- 背景：
  - 本機圖片：在背景執行緒先讀圖檔標頭檢查大小，超過 80 MB、單邊超過 32,768 像素或總數超過 1 億像素時拒絕；解碼上限 2560×1440。
  - MP4 影片：透過系統已安裝的 libvlc（LibVLCSharp 3.10.1）解碼成畫面再顯示，組件可以疊在影片上方；循環、靜音。
    - 畫面最寬 1280 像素，每秒最多更新 24 次。
    - 發行版只附 `libvlc.so.5`（不帶版本號的 `libvlc.so` 屬於 -dev 套件），程式會自行對應到帶版本號的檔案。
    - 找不到 libvlc 或無法解碼時，回退靜態背景並說明原因，不會自行安裝解碼器。
  - 高對比時不顯示裝飾背景。有圖片、影片或動態背景時，時鐘與頂部標籤改用白色。
- 資源釋放：離開首頁、開啟自訂首頁、最小化、隱藏、螢幕鎖定（GNOME）或睡眠（systemd-logind）時，停止時鐘、組件更新與媒體監看，並釋放圖片、影片和背景動畫。
- 測試時的操作紀錄改寫入驗證輸出資料夾，不再寫進使用者的 `~/.local/state`。

## 驗證方法

Linux 外殼測試共 184 項（L1 79 項加上 L2 首頁檢查），在 Windows 與 Linux 都可執行，涵蓋：

- 共用幾何的縮放、吸附與空位搜尋。
- MPRIS 資料解析：時間單位、權限、只接受本機封面。
- 時鐘：三種樣式跨午夜的外框穩定、翻頁與減少動畫。
- 組件：10 種全部加入並保存、上限 12 個、各自的編輯與保存、拖曳取消與縮放保存、方向鍵移動。
- 活動狀態：離頁、鎖定、睡眠與彈窗時暫停，返回後恢復。
- 自訂首頁：顏色驗證、套用與保存。
- 背景：選單只剩靜態、圖片與影片；高對比、圖片在背景執行緒解碼並於鎖定時釋放、找不到檔案、無解碼器時回退，以及標籤顏色。
- 影片生命週期（以假解碼器測試）：離開首頁時釋放、返回時重新建立、減少動畫時停止並說明、播放失敗時回退。
- 確認對話框的 Esc、移除後重新啟動仍保留組件內容。
- 以真實的滑鼠指標事件（包括按下、擷取與放開）拖曳與縮放，確認放開後位置保留並保存，以及拖曳中按 Esc 會還原。
- 以觸控指標事件測試點選、手指大小的把手、拖曳保存，以及長按開啟選單且不移動組件。
- 八個把手都在邊框外、不與標題列重疊，隱藏時不接受點擊。
- 以假 HTTP 服務測試天氣的搜尋、選擇與讀數，以假播放器測試媒體的顯示、控制與監看。

Windows 端完整執行 Release 版 build.ps1，依賴查詢完成：核心 233 項、WPF UI 6,732 項、Linux 外殼 155 項全數通過；之後新增的影片檢查使 Linux 外殼增為 164 項，在 Windows 與 Surface 上另行通過，這段期間沒有再改動 WPF 與核心程式碼。WPF 檢查數量與 L1 相同，代表搬入共用層沒有改變 Windows 行為；150% 縮放下既有的 44 DIP 檢查一樣暫時不中斷，驗證後已還原。

## 使用者實機回報與修正

- 使用者在 Surface 上以觸控拖曳組件：拖曳時會移動，放開後卻回到原位。
  - 原因：放開時先釋放指標擷取，Avalonia 隨即觸發「擷取遺失」，被當成取消拖曳，所以位置還原。
  - 改為先保存位置、再釋放擷取。
  - 先前的測試以程式模擬手勢，沒有經過真實的指標事件；已補上滑鼠與觸控事件的測試。
- 使用者以觸控操作，因此補上上述觸控支援。
- 使用者要求移除背景的兩種動態效果（緩慢漸層、柔和流光），Windows 與 Linux 兩個版本都已移除：
  - 背景選單只剩靜態、本機圖片與本機影片。
  - 舊設定中的這兩個值載入時改為靜態背景。
  - 量測情境 Gradient、Aurora 一併移除。
  - Windows 的 WPF 檢查因此由 6,732 項變為 6,721 項：刪除漸層相關檢查，新增背景選單檢查；核心測試新增 1 項，為 234 項。
  - 下文的實體機紀錄保留當時以漸層測試的過程，作為歷史。
- 使用者回報「＋ 組件」選單與組件右鍵選單的字型和其他文字不同：選單在獨立的彈出層繪製，不會繼承視窗的字型設定，因而用了系統預設字型。現在改由應用程式層級統一設定字型（Noto Sans CJK TC），所有視窗、選單與提示都相同。

## 實體機結果（Surface）

- build-linux.sh：核心 233 項、Linux 外殼 184 項通過；package-linux.sh 打包與啟動檢查通過。
- 以 `--live-mpris` 對真實 session bus 上的測試播放器執行：讀取、播放／暫停、變化通知與回讀狀態全部正確；播放器只收到一次 PlayPause，不支援的「上一首」沒有送出。
- AppImage 以測試設定（翻頁時鐘、漸層背景、媒體、天氣、日曆）啟動並渲染：
  - 媒體組件經真實 D-Bus 顯示測試播放器的歌名、演出者與 0:42 / 3:00 進度。
  - 天氣組件從 Open-Meteo 取得臺北市的即時讀數。
  - 日期與標籤在漸層上為白色，紀錄中沒有錯誤。
- 實機發現並修正了三個問題：
  - Tmds.DBus 寫出的 `arg0Namespace` 大小寫不被 dbus-daemon 接受，播放器上下線監看因此失敗；改為在程式內過濾名稱。
  - 背景建立後沒有再次通知，時鐘日期在漸層上仍是深色。
  - 測試會寫入使用者的紀錄資料夾。

- 影片背景（使用者安裝 `libvlc5 vlc-plugin-base` 之後）：
  - 一開始因為系統沒有不帶版本號的 `libvlc.so` 而無法載入，已改為對應到 `libvlc.so.5`。
  - 以 GStreamer 在 Surface 本機產生的 10 秒 1280×720 H.264 測試影片播放 20 秒：畫面持續更新（約 15 格／秒），會循環，組件與白色時鐘疊在影片上；狀態正常，紀錄中沒有錯誤。
  - 20 秒平均的 CPU 用量（以單一核心為 100%）：

    | 背景 | CPU | 記憶體 |
    |---|---|---|
    | 靜態 | 3.4% | 約 227 MiB |
    | 漸層（每秒 24 次全畫面重繪） | 16% | 約 227 MiB |
    | 影片，加上限制前 | 52% | 約 332 MiB |
    | 影片，加上 1280 寬與 24 格限制後 | 約 43–45% | 約 330 MiB |

  - 逐執行緒取樣顯示，主要成本是 libavcodec 的 H.264 軟體解碼（約 28%），Secondary 的介面執行緒約 6%。
  - Surface 沒有安裝 Intel VA-API 驅動，所以無法硬體解碼。試過略過去區塊濾波與 libvlc 的 fps 濾鏡，都沒有明顯效果，已移除。
  - 安裝 `intel-media-va-driver` 後能否啟用硬體解碼，尚未測試。

## 尚未驗證

- 影片背景的硬體解碼、較高解析度或高位元率影片的 CPU 用量、長時間播放的記憶體走勢，列入 L5。
- 觸控修正後的實際手感：選取、放大的把手、長按選單，以及螢幕鍵盤能否在便箋、待辦、天氣城市等輸入框自動出現（Secondary 經 XWayland 執行），都待使用者在 Surface 上確認。
- 鎖定與睡眠訊號：只以模擬呼叫測試，沒有在實機上真的鎖定或睡眠，以免打斷使用者。
- 長時間資源用量與真實播放器（如 Spotify、Firefox）的封面與控制能力差異，列入 L5。

## 實機驗收步驟

測試機上已建好 `~/Secondary/artifacts/linux/release/Secondary-v1.0.2-linux-x86_64.AppImage`。請確認：

1. 首頁「＋ 組件」加入幾個組件，用觸控或滑鼠拖動、縮放，看吸附虛線與保存是否正常，重新開啟後是否保留。
2. 「自訂首頁」切換三種時鐘與背景，確認圖片背景。
3. 播放音樂（任何支援 MPRIS 的播放器，例如 Firefox 或 Rhythmbox）時，媒體組件能否顯示與控制。
4. 天氣組件輸入城市、選擇地點後顯示讀數。
5. 影片背景：在「自訂首頁」選擇本機 MP4（測試機上有 `~/Secondary/artifacts/video/test-bg.mp4` 可用）。
