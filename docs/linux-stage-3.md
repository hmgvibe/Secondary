# Linux 第三階段：快捷導航、.desktop 啟動器與巨集

狀態：已確認（2026-10-18），使用者指示進入 L4。

## 交付內容

- 核心新增平台規則（`ShortcutRules`）：
  - Windows 沿用原規則：腳本 .ps1／.bat／.cmd，啟動參數只給 .exe，有「視窗快捷鍵」步驟。所有既有呼叫預設使用 Windows 規則，WPF 行為與檢查數量都不變。
  - Linux 規則：
    - 腳本只接受 .sh，以 `/bin/sh` 執行。
    - .sh、.py 等不能用「開啟」步驟繞過腳本確認。
    - 啟動參數只適用於可執行程式與 AppImage。
    - 沒有「視窗快捷鍵」步驟，因為 Wayland 不允許程式向其他視窗送出按鍵，驗證時會說明原因。
- 快捷導航（Avalonia）沿用 WPF 版的行為與文字：
  - 搜尋（150 ms 合併輸入）、分組篩選，以及縱向／橫向分組排列（會保存）。
  - 新增、名稱排序、取消執行。
  - 每個捷徑有編輯、複製、往前／往後移、下次執行重新確認、刪除（先確認）。
  - 最多 200 筆，存於 `~/.config/secondary/shortcuts.json`，損壞時唯讀保留，不覆寫。
- 新增與排序：
  - 可拖入檔案、資料夾、.desktop 啟動器、.sh 腳本與網址，每次最多 20 個；重複、不存在或不支援的項目會略過並說明。
  - 啟動器使用自己的名稱（優先繁體中文 `Name[zh_TW]`）。
  - 滑鼠拖動捷徑可排序，拖到其他分組會改變分組。
  - 觸控長按 0.6 秒開啟選單，平移捲動不受影響。
- 選擇 App（依使用者要求加入）：
  - 「＋ 選擇 App」列出已安裝的應用程式：讀取 XDG 資料目錄（使用者目錄優先）以及 Flatpak、Snap 的匯出目錄中的 .desktop 檔，同名時以使用者的為準。
  - 依 GNOME 規則排除不顯示（NoDisplay、Hidden）、只給其他桌面用（OnlyShowIn、NotShowIn）、程式已移除（TryExec 找不到）以及不是應用程式的項目。
  - 名稱與說明優先顯示繁體中文。可搜尋、複選；已加入的 App 會停用。加入時不會啟動，首次執行一樣要先確認。
  - 依使用者要求，視窗上方有「加入到分組」：可從下拉選現有分組，或輸入新名稱。預設為快捷導航目前篩選的分組，留空則為「未分組」；一次勾選的所有 App 都放進這個分組。
  - 圖示依目前的 GNOME 圖示主題（經 portal 讀取）查找，再依序退到 Yaru、Adwaita、hicolor 與 pixmaps：優先 SVG，其次最大的 PNG。在背景執行緒解碼並快取，失敗時改用文字符號。
  - SVG 以 Svg.Skia 5.1.1（MIT）轉成點陣圖。它使用的 SkiaSharp 3.119 與 HarfBuzzSharp 8.3.1.3 與 Avalonia 相同。較新的 5.2.x 需要 SkiaSharp 4.x，會連帶升級 Avalonia 的繪圖核心，因此不採用。
  - 捷徑方塊若指向 .desktop 啟動器，會顯示該 App 自己的圖示；捷徑資料格式不變，Windows 版不受影響。
- 編輯器：在視窗內的對話層顯示，包含基本資料（名稱、分組、圖示）與編號步驟（開啟、等待、腳本），可上下移動或移除。
  - 檔案選擇經由桌面入口服務。
  - 儲存時套用 Linux 規則，錯誤顯示在底部；儲存不會執行任何東西，Esc 或「取消」會放棄變更。
- 執行（Linux）：
  - 首次執行（以及步驟或腳本內容變更後）會列出所有目標、參數、工作目錄與腳本 SHA256 請使用者確認；.desktop 啟動器還會顯示它實際執行的 `Exec` 指令。確認後記住，拒絕則不執行。
  - 網址、資料夾與文件交給桌面開啟（`gio open`，找不到時改用 `xdg-open`）；.desktop 啟動器用 `gio launch` 啟動；有執行權限的程式與 AppImage 直接啟動並帶入參數。
  - .sh 腳本：讀入內容並比對確認時的 SHA256，把同一份內容寫到 `$XDG_RUNTIME_DIR/secondary/scripts` 的私人副本（僅使用者可讀寫），再以 `/bin/sh` 執行，結束後刪除副本。
    - Linux 的檔案鎖只是建議性的，因此不像 Windows 那樣鎖住原檔，而是改為只執行確認過的那份內容。
    - 以一般權限執行，不使用 sudo 或 pkexec；結束碼非 0 視為失敗，停止後續步驟。
  - 一次只執行一個巨集；任何步驟失敗即停止。
  - 取消只停止 Secondary 自己啟動的腳本程序，不關閉已開啟的程式，也不能撤銷已完成的操作。
  - 進入遊戲模式、隱藏、最小化、螢幕鎖定、睡眠或關閉程式時，取消正在執行的巨集；遊戲模式中不能啟動巨集。

## 驗證方法

核心測試增至 243 項，新增：Linux 腳本副檔名與繞過檢查、參數限制、按鍵步驟的說明、Windows 預設規則不變，以及 .desktop 名稱讀取與 .sh 匯入。

Linux 外殼測試在 Windows 為 213 項，在 Linux 為 240 項：多出的部分是只在 Linux 執行的執行器檢查 8 項與 App 目錄檢查 19 項，後者需要 POSIX 路徑。快捷導航部分：
- 空白狀態與匯入（去重、略過、20 個上限、保存）、搜尋、往後移、拖放排序、選單項目、分組排列切換與保存。
- 執行流程：首次確認、拒絕時不執行、確認後記住、內容變更後重新確認、取消、不能執行時拒絕、步驟失敗停止，以及編輯。
- 視窗內的編輯器：沒有按鍵步驟、Linux 規則錯誤、步驟重排、儲存與 Esc 取消，以及遊戲模式中不能執行。
- App 目錄與選擇器（只在 Linux 執行）：讀取使用者、系統與 Flatpak 目錄；使用者項目覆蓋系統項目；各種排除規則；巢狀資料夾的桌面 ID；繁體中文名稱；SVG 優先、最大 PNG、絕對路徑與找不到時的處理；SVG 轉圖與壞檔回退；選擇器的列出、搜尋、複選、分組預設與指定、提供現有分組、加入、方塊顯示 App 圖示、已加入不可重選，以及 Esc 取消。
- 只在 Linux 上執行（Windows 會略過）：
  - 網址、資料夾與啟動器交給 `gio`；執行檔直接啟動並帶參數。
  - 確認畫面會顯示啟動器的實際指令；按鍵步驟會說明 Wayland 的限制。
  - 腳本在確認後實際執行並刪除私人副本；內容變更後拒絕執行；結束碼非 0 時失敗；取消時立即停止。

Windows 端完整執行 Release 版 build.ps1，依賴查詢完成：核心 243 項、WPF UI 6,721 項（與 L2 相同）、Linux 外殼 213 項全數通過。

Surface 上執行 build-linux.sh：核心 243 項、Linux 外殼 240 項全數通過，打包與啟動檢查通過。在 Surface 上渲染的畫面中，選擇器正確顯示 SVG 圖示與中文說明，方塊也顯示系統實際的「文字編輯器」與 Firefox 圖示。

第一次在 Surface 上執行時，「腳本內容變更後不執行」這項測試卡住約 27 分鐘：
- 原因是測試在介面執行緒上同步等待執行器，而執行器內部的 await 又要回到介面執行緒繼續，兩邊互相等待。程式本身在背景執行緒執行，不會發生。
- 已修正測試輔助方法，並讓執行器的所有 await 都不必回到介面執行緒。
- 之後在 Surface 上執行時加上 10 分鐘上限，避免再次長時間卡住。

## 尚未驗證

- 各類真實程式、AppImage 與 .desktop 啟動器的啟動行為（例如 Flatpak 或 Snap 應用程式的啟動器）。
