# 連線模式第二階段：遠端遊戲監測與快捷鍵同步

狀態：已完成並確認。2026-10-18 在 Windows（Y7000P）↔ Surface 實機驗證快捷鍵同步與串流，使用者隨後以實際遊戲測試通過，要求開始 C3。

## 交付內容

- **遠端遊戲監測**
  - 設備連上主電腦後，遊戲頁改用主電腦的資料，不在設備本機採樣。
  - 只有設備的遊戲頁在畫面上時，設備才請連接助手開始採樣。離開遊戲頁、隱藏、最小化、鎖定或斷線時，連接助手立即停止，連同 PresentMon 與感測助手。
  - 連接助手沿用 WPF 版的 GameTelemetrySession，包括整機 CPU／記憶體／網路、GPU 引擎、感測助手與 PresentMon。設備指定的採樣率、硬體感測開關與遊戲程序都照用。
  - 每秒傳一份快照，只含遊戲頁會顯示的內容：
    - GPU 核心、功耗與顯存讀數，以及 CPU 每種單位的最高值，最多 64 筆。
    - 一般約 2–4 KB。
    - 統計（FPS、1% Low、幀間隔）在主電腦算好。
  - 收到的快照會逐項檢查，包括數值範圍、狀態、字串長度與讀數筆數，不合格就丟棄。
  - 設備超過 3.5 秒沒收到新快照時顯示「過期」，所有數值改為「—」。
  - 每次請求帶編號，舊請求的快照不會混進來。
- **遠端程序選擇**
  - 連線時，程序選擇器列出主電腦的程序，最多 1,000 筆，可依名稱或 PID 搜尋。
  - 選定後由主電腦的 PresentMon 追蹤，程序退出時顯示「已退出」。
  - 切換本機與主電腦來源時，會清除先前選的程序。
- **設備端**
  - WPF：狀態列顯示 `REMOTE · LIVE / LOW`，說明文字標示資料來自主電腦「名稱」。精簡版面的來源列也會標示。
  - Linux：
    - 連線時，MangoHud 區塊改為「選擇主電腦遊戲程序」與「主電腦硬體感測」。
    - Windows 的感測名稱會轉為 Linux 遊戲頁使用的名稱，例如 GPU Core → load、GPU Memory Used → memory-used。
    - 沒開感測時，顯示主電腦所有 GPU 最忙的引擎使用率，並說明開啟感測才有溫度、時脈、功耗與顯存。
  - 斷線後回到這臺設備的資料，遊戲頁說明「已與主電腦中斷連線（原因），改用這臺設備的資料」。重新連上後自動改回主電腦。
- **快捷鍵同步**
  - 設備連線後，把自己設定的快捷鍵送給連接助手，在主電腦上註冊；設備改快捷鍵時同步更新。
  - 在主電腦按下快捷鍵（遊戲中也可），設備就進入或退出遊戲模式。設備本機的快捷鍵照常可用。
  - 快捷鍵只在有設備連線時註冊，斷線即釋放，不會長期佔用主電腦的按鍵。
  - 若主電腦上該組合已被其他程式使用，設備的連線卡片會顯示原因。
- **連接助手系統匣**：新增兩行狀態：
  - 遊戲監測：未使用，或傳送中（採樣率、硬體感測、程序名稱）。
  - 快捷鍵：已啟用的組合，或被佔用的原因。
- **協定**
  - 新增訊息：
    - game-start／game-stop／game-snapshot
    - processes（請求）／process-list（回覆）
    - hotkey／hotkey-status
    - toggle-game
  - 新增通用的請求與回覆配對（id／reply-to），以及逾時。
  - 協定版本仍為 1，因為 C1 尚未發行。
  - 連線結束時，連接助手會取消該連線的所有工作，包括逾時或異常結束。
- 連接助手的建置輸出附上與 WPF 版相同、已驗證雜湊的 PresentMon 與感測助手。

## 驗證方法

- 核心測試：Windows 314 項、Linux 315 項，新增 30 項。
  - 訊息：
    - 請求與快照完整往返；非有限值會以「缺值」傳送。
    - 拒絕 CPU 超過 100%、可用記憶體大於總量、未知狀態與格式錯誤。
    - 讀數上限 64 筆；只送遊戲頁需要的感測。
    - 程序清單上限 1,000 筆，略過無效項目。
  - 迴路連線：
    - 快捷鍵在連線與變更時送出，卡片顯示主電腦回覆；toggle-game 會觸發設備事件。
    - 程序清單；請求無回覆時逾時。
    - 快照到達；忽略其他請求的快照；停止更新後轉為過期，恢復後回到正常。
    - 斷線後不顯示數值，連接助手的工作被取消；重新連線後自動重新請求並重送快捷鍵。
    - 離開遊戲頁時送出停止。
- WPF UI 檢查 6,756 項，新增 15 項。使用真的連接助手系統匣元件與假的採樣來源：
  - 快捷鍵在主電腦註冊並顯示於卡片與系統匣；模擬主電腦按鍵（WM_HOTKEY）時，設備進出遊戲模式，連接助手隨之開始或停止採樣。
  - 遊戲頁顯示主電腦的 FPS、CPU、GPU、顯存，以及 REMOTE 狀態。
  - 程序選擇器列出主電腦的程序，選定後由主電腦追蹤。
  - 斷線時回到本機資料並說明原因，連接助手釋放快捷鍵；重新連線後再次註冊。
- Linux 外殼檢查：Windows 306 項、Linux 340 項，新增 17 項：
  - 感測名稱轉換。
  - 與 WPF 相同的流程，加上 MangoHud 區塊與主電腦選項的切換、主電腦硬體感測開關。
- 本機 UI 檢查照例暫時放寬 150% DPI 下已知的 44 DIP 導航檢查，跑完已還原。
- 實機（Windows Y7000P 執行 C2 連接助手 ↔ Surface 執行 C2 AppImage）：
  - Surface 重新啟動後自動連回連接助手。
  - 在 Windows 以系統按鍵事件送出 Ctrl+Alt+G（Surface 設定的快捷鍵），Surface 進入遊戲模式，再按一次即退出（以 Surface 設定檔的模式值確認）。
  - 連接助手的資源用量：

    | 情境 | CPU（單核） | 私有記憶體 | 工作集 | 執行緒 |
    |---|---|---|---|---|
    | 設備在遊戲頁，低採樣率、未開硬體感測，30 秒平均 | 0.68% | 23.6 MB | 77 MB | 18 |
    | 設備已連線但不在遊戲頁，30 秒平均 | 0.10% | 24.3 MB | 77 MB | 18 |

## 尚未驗證

- 主電腦開啟硬體感測時的感測助手讀數與資源用量。
- Windows 設備連到另一臺 Windows 主電腦（WPF 端目前只在同一臺電腦的迴路上驗證）。
- 全螢幕獨佔模式的遊戲中，主電腦快捷鍵是否被遊戲攔截。這與 WPF 版的快捷鍵相同。

## 注意事項

- 如果主電腦也執行 WPF 版 Secondary，並用同一組快捷鍵，兩者只有一個能註冊成功；連接助手會在設備卡片與系統匣說明。
- 程序選擇器的選單在測試中只檢查內容，不檢查是否保持開啟，因為測試視窗不在前景時，WPF 選單會立刻關閉。
