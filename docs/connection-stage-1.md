# 連線模式第一階段：連接助手、搜尋、配對與加密連線

狀態：已完成並確認（2026-10-18 使用者在 Surface 上實機配對並連線成功，隨後要求開始 C2）。這個階段只建立連線；遊戲監測、快捷鍵同步、媒體與捷徑在 C2、C3 加入。

## 交付內容

- **Secondary.Windows 共用庫**
  - 把 WindowsSampler、GpuCounter、PresentMon（含雜湊檢查與工作階段租約）、CaptureJob、感測助手用戶端與 GameTelemetrySession 從 WPF 專案搬過來，讓 WPF 版與連接助手共用。
  - 只搬移、不重構：命名空間改為 `Secondary.Monitoring`，內容不變。
  - 刻意不使用 `Secondary.Windows` 命名空間，因為它會在 Secondary.App 內遮蔽 WinRT 的 `Windows.*`。
- **連線協定**（Secondary.Shared，Windows 與 Linux 共用）
  - TCP 上的 TLS 1.3／1.2，雙方各有自簽 ECDSA P-256 憑證，雙向驗證。
  - 只接受配對時記住的憑證指紋；同一位址的憑證若改變則拒絕，不會自動信任。
  - 訊息格式為長度前綴的 JSON，單則上限 1 MiB，帶協定版本；版本不符時拒絕並說明。
  - 每 5 秒心跳一次並量測延遲；20 秒沒有任何訊息即視為斷線。
  - 身分憑證存為使用者私有的 PKCS#12（Linux 權限 0600），無法讀取時另存舊檔並重新建立。
  - 配對清單以原子方式寫入，損壞時另存並重新開始，最多 8 筆。
- **配對**
  - 採用與藍牙「Passkey Entry」相同的逐位元承諾：6 位數配對碼分 20 輪，每輪先承諾、後揭露，承諾內容綁定雙方看到的兩個憑證指紋。
  - 中間人每一輪都必須先猜才能看到答案，成功機率約百萬分之一；傳送的內容也無法用來離線暴力破解配對碼。
  - 配對碼只在主電腦按「開始配對」後的 2 分鐘內有效，錯誤 3 次即作廢；同一時間只能有一臺設備在配對。
  - 設備確認主電腦的每一輪都正確後，雙方才記住對方。
- **搜尋**：設備在每個 IPv4 網路的廣播位址及 255.255.255.255 上送出 UDP 詢問（連接埠 47610），連接助手回覆名稱、連接埠（47611）與指紋。也可以手動輸入 IP 或 IP:連接埠。
- **連接助手（Secondary.Connect.exe，Windows 系統匣程式）**
  - 沒有主視窗，以一般權限執行，單一實例；重複啟動時只顯示目前狀態。
  - 系統匣選單：連線狀態、主電腦名稱與指紋、問題提示、開始配對、已配對設備（含上次連線時間，可移除，移除前會確認）、登入時啟動（使用者層級的 Run 機碼，預設關閉）、結束。
  - 配對視窗顯示大字配對碼、倒數與狀態，關閉視窗即結束配對。
  - 同一時間只接受一臺設備連線，同一臺設備重連時會取代舊連線；從主電腦移除設備時會立即中斷它的連線。
  - 最多同時處理 4 個尚未驗證的連線，握手限時 15 秒。
  - 平時只監聽，不採樣任何資料。
- **設備端「連線模式」卡片**（WPF 與 Linux 版，放在設定頁的快捷鍵卡片之後）
  - 第一次開啟設定頁時自動搜尋一次，也可以手動「搜尋主電腦」。
  - 列出搜尋到的主電腦與已配對的主電腦：已配對的可以「連線」與「移除配對」，未配對的按「配對…」會自動填入位址。
  - 輸入主電腦 IP 與配對碼後按「配對並連線」；狀態、延遲與錯誤原因會以讀屏可讀的方式更新。
  - 連線後自動重連（1、2、5、10、30 秒退避）；連續失敗時重新搜尋同一指紋，以更新變動的 IP。
  - 下次啟動時自動連回上次連線的主電腦；「中斷連線」後則不再自動連線。
  - 「移除配對」會先確認，並請主電腦一併移除。
  - 主電腦移除這臺設備、主電腦身分改變或版本不符時停止重試，並說明原因。
  - 本機識別碼（指紋前 16 碼）顯示在卡片底部，可與主電腦比對。
  - 無法建立本機身分時，卡片顯示原因，其他功能不受影響。效能量測模式不啟用連線。

## 驗證方法

- 核心測試：Windows 284 項、Linux 285 項。新增 41 項連線檢查（Linux 多 1 項私鑰檔權限檢查），全部在本機迴路上執行：
  - 身分建立與重新載入、損壞時重建、指紋顯示、配對碼格式；配對清單的上限、取代、移除、自動連線與損壞處理。
  - 配對：正確配對；差一個數字時雙方都失敗；中間人換了憑證時，即使配對碼正確也失敗。
  - 連線流程：
    - 搜尋、未配對拒絕、未開始配對時拒絕、錯誤碼倒數與 3 次作廢、作廢後不能再用、失敗時雙方都不記錄。
    - 配對成功、連線與心跳延遲、記住自動連線、單一連線、版本不符、身分改變。
    - 主電腦移除後設備停止重試、設備移除時主電腦一併移除、中斷連線、啟動時自動連回、連接助手消失後自動重試。
- WPF UI 檢查 6,741 項（新增 20 項）：
  - 無法使用時的說明、卡片位置、搜尋列出、選擇後填入位址、短碼與未開始配對的提示。
  - 連接助手的系統匣選單、登入時啟動、配對視窗顯示配對碼、配對成功後視窗狀態與卡片狀態、中斷與重新連線。
  - 從系統匣移除（拒絕時保留）、設備端移除配對。
- Linux 外殼檢查：Windows 289 項、Linux 323 項，新增 13 項，涵蓋 Linux 卡片的同一流程；移除配對使用視窗內的確認對話框。
- Surface（Ubuntu 26.04）實機：Linux 建置與全部測試通過，已打包 AppImage 並換上執行。從 Surface 對這臺 Windows（Wi-Fi，192.168.1.113）廣播搜尋，收到連接助手的回覆，TCP 47611 也能連上。
- 使用者實機配對（Windows「Y7000P」連接助手 ↔ Surface，以觸控輸入配對碼）：
  - 雙方各自記下對方的憑證指紋，且與實際憑證一致。主電腦記錄的 Surface 指紋，與用 openssl 從 Surface 身分檔算出的 SHA-256 相同；Surface 記錄的主電腦指紋，與搜尋回覆中的指紋相同。
  - Surface 標記為下次自動連線；Linux 的配對與身分檔權限皆為 0600。
  - 兩邊各有一條已建立的 TCP 連線（Surface secondary ↔ 連接助手 47611）。
  - 連接助手在一臺設備連線、只有心跳時：30 秒平均約佔單核 0.21%，私有記憶體 24 MB，工作集 85 MB（含共用的 WinForms 程式庫頁面，開過選單與配對視窗後增加）。

## 尚未驗證

- Windows 設備連到另一臺 Windows 主電腦（目前只在同一臺電腦的迴路上驗證）。
- 連接助手的長時間閒置資源：私有記憶體 24 MB 符合約 40 MB 的目標，但工作集為 85 MB；C2 量測時再確認長時間的變化。
- 連接助手尚未加入 Windows 發行包，C2 或 L5 打包時一併處理。

## 注意事項

- Windows 網路需設為「私人網路」，並允許連接助手通過防火牆；公用網路下其他設備通常連不進來。
- 連接助手需要 .NET 10 桌面執行環境；正式發行包會採用自包含版本。
